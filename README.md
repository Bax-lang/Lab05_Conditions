## Ответы на вопросы

1. **Чем `int.TryParse()` безопаснее `int.Parse()`? В каких случаях стоит использовать каждый?**
`int.Parse()` аварийно завершает программу, если пользователь ввёл не число, а текст. `int.TryParse()` не ломает программу, а просто возвращает `false`. `int.Parse()` можно использовать, только если мы точно уверены, что на вход придёт число, а `int.TryParse()` — всегда при пользовательском вводе.

2. **Когда `switch` удобнее, чем цепочка `if/else if`? Приведите пример из реальной жизни.**
`switch` удобнее, когда нужно сравнить одну переменную с несколькими конкретными значениями. Пример из жизни: выбор пункта в голосовом меню банка (нажмите 1 — узнать баланс, нажмите 2 — заблокировать карту, нажмите 3 — связаться с оператором).

3. **Что произойдёт в `switch`, если убрать `break` после одного из `case`?**
Если внутри `case` есть код и убрать `break`, возникнет ошибка компиляции (в C# нельзя проваливаться из непустого `case` в следующий). Если `case` пустой (без кода), то выполнение просто перейдёт к следующему `case` (группировка условий).

4. **Чем отличается `=` от `==` в C#? Почему это частая ошибка?**
`=` — это оператор присвоения (записывает значение в переменную), а `==` — оператор сравнения (проверяет, равны ли значения). Новички часто путают их по привычке из математики, где один знак равенства означает сравнение.

5. **Можно ли написать тернарный оператор внутри другого тернарного оператора? Приведите пример из кода лабораторной и оцените читаемость такого кода.**
Да, можно. Пример из лабораторной:
`string weather = temp >= 20 ? "тепло" : (temp >= 0 ? "прохладно" : "мороз");`
Читаемость такого кода плохая — в нём легко запутаться, поэтому для нескольких условий лучше использовать обычный `if/else`.
